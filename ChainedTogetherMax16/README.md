# Chained Together Max 16

Chained Together 用の非公式UnchainedTogetherベースModです。ホスト画面の人数選択肢を1〜16人に増やし、選択値をゲーム側の人数上限へ反映します。5人以上でゲーム標準のチェーン接続処理が終了した後、ホスト側で隣接プレイヤーの接続とチェーン実体を確認し、欠けている部分を補います。

## 導入

1. Chained Togetherを終了します。
2. `ChainedTogether\Binaries\Win64\d3d12.dll` をこのフォルダーの `d3d12.dll` に置き換えます。
3. Steamから起動し、Host Gameの人数欄に1〜16人が表示されることを確認します。

今回のチェーン補修の直前に使われていたDLLは `d3d12.dll.pre-chain-sync` に保存しています。戻す場合はゲームを終了し、このファイルを `d3d12.dll` に戻してください。さらに古いDLLも `d3d12.dll.pre-sdk-fix`、`d3d12.dll.pre-vtable-fix`、`d3d12.dll.previous` に残しています。

## 実装内容

- ホスト画面の人数コンボボックスに5〜16人を追加します。
- 選択値をゲームインスタンスとホスト側の `GameSession.MaxPlayers` に同期します。
- 選択肢追加と人数同期は、Unrealのホスト画面が存在するときに行います。
- ホストで5人以上のとき、ゲーム開始・自動接続・救助後の標準処理を終えた時点で、隣接プレイヤー間の複製対象の接続配列とチェーン実体を確認します。閉じたチェーンでは先頭と末尾も確認します。欠けている接続だけをゲーム標準の関数で補います。クライアント側の複製はゲーム本体のRepNotifyとチェーンアクターに任せます。

## 検証状況

- Windows x64 `Release` ビルド成功。
- 実プレイで人数欄が1〜4人のままなのを確認。旧SDKのGWorld、GObjects、名前取得アドレスと、ホスト画面の人数欄オフセットが現在のゲームと異なることを実行中メモリと反射情報で確認し、修正しました。
- 現在のゲーム実行ファイルSHA-256は `4CA3CCE06E965A9B1E3C6438FC8EB93DE5B422C813275A92761C67563E85145B` です。ゲーム更新後はアドレスが変わる可能性があります。
- 修正版でSteamから通常起動し、`[Max16]`ログにフックの実到達、ホスト画面の検出、16項目追加、16人選択の記録を確認しました。Host Game画面でも1〜16人の表示と「16 Players」の選択を確認しました。16人同時接続は未確認です。
- チェーン補修を含むReleaseビルドは成功しました。5人以上の実接続が用意できていないため、チェーン補修の実行と各クライアントへの同期は未検証です。
